# OmaDBngin 1.7: pro panel, light on the machine

Date: 2026-10-29 · Status: approved 2026-10-29; built (see Changes during the build)

OmaDBngin stays a bar widget with its popup panel (not a window app). 1.7 makes the panel
complete for daily work while costing nothing when nobody looks at it.

## Rule zero: light on CPU, RAM and GPU

Every feature below follows these, and the release is measured against them.

| State | Allowed work |
|---|---|
| Panel closed | The two existing event watchers (Docker events via `curl` on the socket, ~1 MB; `journalctl -f` for native units) and one `dbctl state` per 60 s. No timers that repaint, no animations, no stats, no disk scans, no network. |
| Panel open | `dbctl state` every 3 s (as today). Stats come from kernel files (cgroup v2 `memory.current`, `cpu.stat`; systemd `MemoryCurrent`, `CPUUsageNSec` in the one `systemctl show` call already made), never `docker stats`. Readiness is one TCP connect per running server. Disk size is computed once per open and cached for 5 min. |
| Logs view open | One `tail -f`/`docker logs -f` for that one server, killed when the view closes. |

- Nothing animates unless an action is running (spinner only on the busy row).
- Images render at the screen's pixel density once; no shaders, no layer effects, no blur.
- Budget, measured before release on this machine: closed panel adds ≤ 0.1 % CPU over 10 min and no
  RSS growth in `omarchy-shell`; open panel ≤ 1 % CPU averaged over 60 s with 5 servers running.

## Features

### 1. Bar icon status
- Badge with the number of running servers (hidden at 0, setting to turn off).
- Red dot when a server stopped on its own (Docker `die` with non-zero exit, systemd `Failed`).
  Cleared when that server starts again or the panel is opened.
- Tooltip: each server with state, engine, version and port. Built from the last snapshot: no
  extra work.

### 2. Richer server rows
- Uptime, memory, CPU % (delta of CPU time between two 3 s snapshots), data size on disk.
- **Ready** check: running and accepting TCP connections on its port ("starting…" until then).
- Docker data size uses the volume's mountpoint when readable; otherwise "—" (never sudo).

### 3. Search
- Filter box at the top when there are more than 5 servers: matches name, engine, version, port,
  stack. Esc clears.

### 4. Stacks
- A stack is a named group of servers (e.g. `shop` = Postgres + Redis). Shown as a header with
  Start all / Stop all for that stack; a server belongs to at most one stack.
- Stored by `dbctl` in `~/.local/share/omadbngin/stacks.json`;
  `dbctl stack list|create|delete|add|remove|start|stop`.

### 5. Start all / Stop all
- In the panel header. Starts or stops every server (or only the filtered ones when searching).

### 6. Copy as…
Per server, copies one of: URL, `DATABASE_URL=…`, Laravel `.env` lines (`DB_CONNECTION`,
`DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`; `REDIS_*` for Redis/Valkey),
Django `DATABASES` snippet, JDBC URL, `psql`/`mysql`/`redis-cli`/`mongosh` command line.
`dbctl copy <name> [format]`; the password is included only when the server has one.

### 7. Logs in the panel
- The last 200 lines of the server log, following live while visible, with "Open in terminal"
  kept for the full log.

### 13. Settings panel
Opened from a gear in the panel header, right-click on the bar icon, or a keyboard shortcut.
Saves straight into `shell.json` with a rolling backup, the way OmaColorBar 1.3 does.

- **Position on the bar**: section (left / center / right) and place in it (first, last, or
  before / after a chosen widget, picked from the widgets in that section). Moves this widget's
  own entry in `bar.layout`; nothing else in the layout changes.
- **Bar icon**: badge on/off, crash dot on/off, show the running count as text next to the icon.
- **Panel**: compact rows (one line per server) or detailed (stats line), stats on/off (off =
  no stats work at all), default mode for new servers (native / Docker).
- **Defaults**: port per engine, username, backup folder (instead of `~/Downloads`).
- **Notifications**: off by default in 1.7 (the toggle is reserved for 1.8 crash/backup notices).
- **Shortcut**: `dbctl bind` / `dbctl unbind` add or remove SUPER+ALT+D in
  `~/.config/hypr/bindings.lua` (refuses if taken); the shortcut opens the panel through IPC.
- **Reset to defaults**.

## Out of scope (1.8)

Edit / rename / clone servers, version upgrades, engine manager, automatic backups,
notifications.

## Implementation notes

- `dbctl state` gains per-server `cpuUsec`, `memory` (Docker from cgroup files, native from
  `systemctl show`), `ready`, and the stacks; `dbctl sizes` returns data sizes (separate, cached
  by the panel). All plain file reads or one call per command.
- Settings live in the widget's own entry in `shell.json` (`bar.layout`), as today's settings do.
- Version 1.7.0; README "What's new", "Updating" and poster updated before the marketplace
  update request.
- Tests: Docker suite extended for `copy` formats, stacks, state fields; QML safety tests for
  the panel; a measurement script for the budget above.

## Changes during the build

- Shortcut is SUPER+ALT+D: SUPER+CTRL+D and SUPER+CTRL+ALT+D are Omarchy defaults.
- Open panel polls every 5 s (not 3 s); start, stop and crashes still arrive instantly through
  the event watchers.
- `dbctl state` got cheaper: the OmaDB migration check runs until it has nothing left (then a
  marker skips it), Docker is read through its socket with `curl`, fewer `jq` runs
  (0.07 s → 0.034 s CPU per run). Disk sizes left `state` for `dbctl sizes`.
- Row tools (copy as, stack, log, backups) are created only while open: every refresh rebuilds
  the rows, and hidden tools cost ~1.8 % CPU with the panel open.
- `qs … ipc call omadbngin settings` opens the settings page.
- Measured (one Redis server, 60 s, whole shell): closed 0.42 % (1.6.1: 0.37 %, noise),
  open 0.85 % (1.6.1: 1.73 %); RSS flat.
